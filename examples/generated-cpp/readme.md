# cpdocs example: generated headers

Part of the public API of this library is generated by the build, and none of it is checked in:

- `acme/version.hpp` is written by `configure_file` when the build is configured, from
  `cmake/version.hpp.in` and the version given to `project()`;
- `acme/status.hpp` is written by a build target that runs `cmake/generate-status.cmake` on the table
  `data/status-codes.txt`, one documented enumerator per row.

The checked-in header `include/acme/core.hpp` includes both. The build hook in `docs/cpdocs.yml`
configures the project and builds the target `acme-generated-headers`, and the manifest names the
generated include directory as an API root marked `generated`. cpdocs reads the headers from the
build directory once the hook has returned, so the reference documents the generated declarations
at their include paths and marks those files as generated by the build.

```console
cpdocs build          # API reference in build/cpdocs/current
properdocs build      # project site with the versioned API, needs a Git repository
```
